## "고쳤고, 머지됐고, CI도 green인데요?"

페이지네이션 버그가 하나 있었다. 특정 해상도에서 표 아래 페이저(‹ 이전 1/4 다음 ›)가 화면에 안 보여서 다음 페이지로 못 넘어가는 문제. 수정 PR을 올렸고, lint·build·CI 전부 통과해서 머지했다. 끝난 줄 알았다.

며칠 뒤 통합 E2E 테스트를 돌리다 1366×768 해상도에서 그 화면을 열었는데 — **페이저가 여전히 안 보였다.** 분명히 고쳤고, 분명히 green이었는데.

## 무슨 일이 있었나

원래 코드는 표 영역에 `max-height: 560px`를 박아두고 있었다. 수정 PR은 이걸 떼고 `flex: 1`로 바꿨다. "부모 높이를 채우고 남는 공간만큼 표가 스크롤되면 페이저는 자연히 아래 고정되겠지"라는 의도였다.

문제는 그 `flex: 1`이 효과를 보려면 **조상 요소들이 끊김 없이 높이가 제한된 flex 컬럼**이어야 한다는 것. 그런데 중간 조상들이 `display: block`이었다.

```
.pss-root (flex:1)        ← 여기까진 의도대로
  └ .ds-section (block)   ← 여기서 끊김
    └ .pv-s2m-tab (block)
      └ .content (block)
```

block 조상은 자식의 `flex:1`을 가둬주지 않는다. 그래서 표는 콘텐츠 높이(2000px+)로 그냥 쭉 펼쳐졌고, 페이저는 화면 한참 아래(`top ≈ 2400px`, 뷰포트는 768px)로 밀려났다. **오히려 `max-height`를 떼면서 기존보다 더 나빠진 것.**

수정은 단순했다 — 조상 레이아웃에 의존하지 않도록 뷰포트 상대값으로 다시 가뒀다.

```css
.pst-wrap {
  flex: 1;
  min-height: 160px;
  max-height: calc(100vh - 470px); /* 그리드 위 chrome + 페이저 높이 */
}
```

이번엔 머지 전에 1280×720부터 1920×1080까지 실제 브라우저로 페이저가 보이는지 눈으로 확인하고 머지했다.

## 왜 CI가 못 잡았나

당연하다. **이건 레이아웃 문제고, 단위 테스트·빌드·lint가 검증하는 영역이 아니다.** CSS가 문법적으로 멀쩡하고 빌드가 통과하는 것과, 그 CSS가 실제 DOM 트리 위에서 의도한 픽셀을 만들어내는 것은 완전히 다른 문제다.

`flex:1`은 그 자체로 틀린 코드가 아니다. 조상 체인이라는 *맥락* 안에서만 틀렸다. 그리고 그 맥락은 코드를 읽어서가 아니라 **실제 화면을 띄워봐야** 드러난다.

## 그래서 얻은 것

머지 기준을 변경의 성격에 따라 다르게 잡기로 했다. 핵심은 **"이 변경이 망가졌을 때, 그걸 잡아낼 수 없는 검증 방법이 무엇인가"**를 먼저 묻는 것.

| 변경 성격 | 머지 전 필요한 검증 |
|---|---|
| BE 로직 (분기·계산·검증) | 단위 테스트로 충분 |
| **FE 시각·레이아웃** | **실해상도 라이브 시각검증 필수** |
| 오래된 베이스의 PR | 현재 main에 합쳐 재빌드까지 확인 |

"merged·green"은 "그 검증 도구가 커버하는 범위 안에선 문제없음"이라는 뜻일 뿐, "동작함"의 동의어가 아니다. 합쳐지는 것(merge)과 동작하는 것(work)은 별개다.

통합 E2E를 돌린 가장 큰 수확이 바로 이거였다 — 이미 "끝났다"고 체크해둔 항목이 실은 살아있지 않았다는 걸, 사용자가 겪기 전에 잡았다는 것.
